บทที่ 1: ข้อมูลปฐมภูมิและสมรรถนะภาพรวมของระบบ (General Information & System Capabilities)
===================================================================================================================
โครงการ "PEA PQ SMART TRACKER" เป็นระบบบริหารจัดการ บันทึก และติดตามคุณภาพไฟฟ้าสำหรับโรงผลิตไฟฟ้าเอกชน (VSPP / SPP) 
ที่เชื่อมต่อเข้ากับสถานีบริการไฟฟ้าย่อยของ การไฟฟ้าส่วนภูมิภาค (PEA) โดยออกแบบสถาปัตยกรรมและอินเตอร์เฟสให้รองรับการใช้งานอันมีประสิทธิภาพสูง 
ปลอดภัย เป็นมิตร และสามารถทำงานอย่างต่อเนื่องบนระบบคลาวด์และหน่วยปฏิบัติการสนาม (Field Operations)

ขีดความสามารถสมรรถนะหลัก (System Core Capabilities):
1. การจัดการความปลอดภัยขั้นสูง (Multilayer Security Guard): 
   - ระบบควบคุมการเข้าถึงข้อมูลตามบทบาทผู้ใช้ (Role-Based Access Control)
   - ความมั่นคงปลอดภัยระดับแถวข้อมูลและคอลเลกชันบนระบบ Firebase Firestore ด้วยระบบความปลอดภัยแบบยืนยันตัวตน (Firebase Authentication Context)
2. การคำนวณพิกัดภูมิศาสตร์และการกั้นขอบเขตกิจกรรมป้อนงาน (Geofencing Operational Limit):
   - การประมวลผลโลเคชั่นจาก GPS Hardware ในเบราว์เซอร์ เพื่อระบุความแม่นยำสูง
   - ระบบคำนวณทางคณิตศาสตร์แบบดิ่งโค้งรอบผิวโลก เพื่อกำจัดปัญหาการส่งงานตรวจสอบสวมรอยนอกพื้นที่ดำเนินการ (GPS Fabricating/Spoofing Prevention)
3. การสลับการทำงานหลากหลายภาษา (Dynamic Localization):
   - รองรับสองภาษา (ภาษาไทย TH / ภาษาอังกฤษ EN) แบบโต้ตอบได้ทันทีทั่วทั้งแอปพลิเคชัน (Localization Engine)
4. การออกแบบสำหรับการใช้งานบนอุปกรณ์พกพาอันยอดเยี่ยม (Mobile-First High-Density Fluid UI):
   - หน้าจอประยุกต์การกางเลย์เอาต์โครงสีกระจายตัว (Theme Adaptability) จากแบล็คบอร์ดสีมืดที่สบายตาไปสู่โทนขาวเรียบหรู
   - ได้รับการออกแบบเลย์เอาต์ตามมาตรฐานการสัญจรของสายตาและการควบคุมด้วยนิ้วมือ (Optimal Touch-Targets)

บทที่ 2: ลำดับขั้นตอนการทำงานและกระบวนการเวิร์กโฟลว์ (System Workflow Procedures)
===================================================================================================================
ขั้นตอนการทำงานของระบบถูกจัดตั้งขึ้นด้วยความรัดกุมรอบคอบตามมาตรฐานวิศวกรรมการตรวจประเมิน เพื่อรักษาความเป็นกลางของผลตรวจวัด:

ขั้นตอนที่ 1: การลงทะเบียนและการขึ้นครองระบบ (Onboarding & User Provisioning)
  - ผู้ดูแลระบบ (Admin) หรือผู้ผลิตไฟฟ้า (Vendor) ทยอยจัดทำทะเบียนประวัติบัญชี
  - ระบบเก็บค่าโครงสร้างสังกัด PEA (peaOffice) ประวัติวิชาชีพ และลายเซ็นดิจิทัลประมวลผลแรกเริ่ม

ขั้นตอนที่ 2: การสร้างคำร้องขอตรวจสอบอุปกรณ์เชื่อมโยง (Inspection Request Creation)
  - ผู้ประกอบการ (Vendor) เป็นผู้สร้างประวัติโรงพลังงานไฟฟ้าและส่งคำขอตรวจสอบความมั่นคงของสถานีคุณภาพ (PQ Compliance Service)
  - คำร้องจะเปลี่ยนสถานะเป็น "PENDING (รอประเมิน)" ส่งต่อไปสู่สายงานควบคุมการทำงานของฝ่ายวิศวกรรม PEA

ขั้นตอนที่ 3: การมอบหมายงานและการรับเรื่อง (Job Assignment & Acceptance)
  - วิศวกรผู้ตรวจ (Inspector) เข้าสู่หน้าจอแดชบอร์ดรับรายงาน เลือกจัดสรรเวลาทำการ และเปลี่ยนสถานะคำขอเป็น "ACCEPTED (รับงาน)"
  - ทันทีที่รับเรื่อง ระบบจะดึงพิกัด GPS ประจำโรงงานไฟฟ้าต้นเรื่องเพื่อปักหมุดประดับรอบเส้นทาง

ขั้นตอนที่ 4: การลงสนามปฏิบัติการและการเปิดพิกัด Geolocation (Site Verification & Geofence Activation)
  - วิศวกรเดินเท้าเข้าไปยังหน้างานอุปกรณ์ไฟฟ้าจริง
  - ณ จุดตรวจวัด วิศวกรกดปุ่ม "ระบุพิกัดปฏิบัติงาน (Verify Location)" บนเบราเซอร์
  - ระบบลอยสัญญาณดาวเทียมผ่าน Geolocation API ตรวจห่างเทียบพิกัด หากห่างจากจุดเป้าหมายไม่เกิน 500 เมตร ปุ่มส่งแบบฟอร์มตรวจสอบจะถูกปลดล็อคโดยสมบูรณ์
  - หากอยู่นอกระยะเกิน 500 เมตร ระบบแจ้งเตือนขัดขวางทันที (Block Site Inspection)

ขั้นตอนที่ 5: บันทึกข้อมูลรายงานและการสแกนข้อบกพร่อง (Inspection Data Entry)
  - วิศวกรกรอกข้อมูลความปลอดภัยตามเช็คลิสต์มาตรฐาน (เช่น อุณหภูมิสายส่ง แรงดันฮาร์มอนิก การเชื่อมต่อสายดิน ประตูตู้ควบคุม)
  - แนบภาพหลักฐานความพร้อมของสวิตช์ย่อย พร้อมเขียนบรรยายจุดที่ต้องปรับปรุง หรือสร้างสถานะการตรวจพบความผิดปกติเด่นชัด

ขั้นตอนที่ 6: การยื่นรายงานและยืนยันตัวตนด้วยลายเซ็น (Inspection Submittal & Signature Verification)
  - วิศวกรตรวจทานข้อมูล วาดพาร์ทลายเซ็นลงสัมผัส (Digital Canvas Signature) 
  - ทรานส์ข้อมูลข้อทั้งหมดเป็น Inspection Document ยิงบันทึกขึ้น Firestore
  - เปลี่ยนสถานะคำร้องเป็น "AWAITING_APPROVAL (รออนุมัติ)"

ขั้นตอนที่ 7: การกลั่นกรองและอนุมัติรายงานเชิงวิศวกรรม (Verification & Executive Approval)
  - หัวหน้างาน/ผู้บริการ (Manager) สแกนเอกสารจากช่องพอร์ทัลตรวจรับ
  - อนุมัติผลเพื่อปิดคำร้องเป็น "COMPLETED (ตรวจแล้วเสร็จ)" หรือกดปฏิเสธในกรณีข้อมูลไม่สมบูรณ์และสั่งให้วิศวกรส่งชุดวัดใหม่

บทที่ 3: แค็ตตาล็อกฟิเจอร์และโมดูลการทำงานภายในแอปพลิเคชัน (All System Features & Functions)
===================================================================================================================
แอปพลิเคชันประกอบไปด้วยองค์ประกอบและโครงสร้างหน้าต่างย่อย (Sub-Modules) ที่ประสานเข้าด้วยกันอย่างไร้รอยต่อดังนี้:

1. ระบบการยืนยันตัวตนและความปลอดภัยช่องทางเข้า (Universal Login System):
   - รองรับการเข้าระบบผ่านอีเมลและรหัสผ่านส่วนบุคคลอย่างปลอดภัย
   - ถอดปุ่ม "ลงชื่อเข้าใช้ด้วย Google" ออกเพื่อรักษามาตรฐานของเครือข่ายความมั่นคงระดับภายใน (PEA Internal Application Only Context Environment)
   - ป้องกันรหัสผ่านไม่ผ่านตามกฎ และหน่วงเวลาเตือนภัยในการพยายามเข้าสู่ระบบผิดพลาดซ้ำๆ

2. แดชบอร์ดภาพรวมสถิติวิศวกรรม (Dynamic Metric Dashboard):
   - แถบข้อมูลสรุปกำลังการผลิตรวม (Total Generation Capacity), อัตราความคืบหน้าการตรวจงาน (Audit Progress), รายวิจัยสถิติปัญหา (Open Complaints Index)
   - ใช้ไลบรารีกราฟ `recharts` ในการแสดงแนวโน้มปริมาณความซับซ้อนของค่า PQ, ด่วนปริมาณ, และจำนวนเคสคั่งค้าง แบ่งกลุ่มประเภทชัดเจน

3. พอร์ทัลการจัดการประวัติตู้โรงผลิต (Power Plant Management):
   - หน้าจอสร้างและบำรุงฐานข้อมูลผู้ปฏิรูปผลิตไฟฟ้า (VSPP/SPP)
   - เก็บค่าพิกัดพิกเซล ละติจูด ลองจิจูด ตำบล อำเภอ จุดร้อยรับกระแส และเป้าหมายการจ่ายพลังงานแผง

4. ระบบบันทึกข้อบกพร่องเชิงรับ (Customer Complaint Taskforce & Incident Center):
   - ให้วิศวกรหรือพาร์ทเนอร์สแกนส่งเหตุขัดข้องเกี่ยวกับสัญญาณรบกวนไฟกระตุก (Swells/Sags) ไฟวูบดับ หรือระบบแผงดรอป
   - จำแนกประเภทความคุ้มกันปัญหา (Technical, Accounts, System Bug, Data sync) เพื่อกระจายส่งสายแก้รวดเร็ว

5. หน้าปฏิบัติตรวจสอบความปลอดภัยนอกสถานที่ (Safety & Equipment Inspection Module):
   - จัดแสดงแนวฟอร์มตอบคำสั่งสี่หน้าย่อย: ข้อมูลตู้ควบคุมหลัก, แบบเช็คตรวจอุปกรณ์, บันทึกแนบภาพสเตชั่น, หน้าจอรับลายมือชื่อ
   - ฝังกลไก Geolocation API และชุดตรวจทวน Geofencing

6. ศูนย์รวมการตั้งค่าแอพพลิเคชัน (Settings & Personalization):
   - สลับแถบภาษา (TH / EN) ตลอดเวลาอย่างฉับไว
   - เครื่องมือเปลี่ยนกลุ่มโครงสี (Light Mode / Dark Mode) ช่วยในการลดค่าน้ำหนักสายตาในการวิเคราะห์แดดจ้าหรือที่มืด
   - คลีนพอร์ตแคช (Developer Option Sandbox System Clear) สำหรับพนักงานทดลองระบบจำลองผลงาน

บทที่ 5: โครงสร้างข้อมูลและการออกแบบฟังก์ชั่นจัดเก็บข้อมูลในระบบ Firebase Firestore (All Database Structure)
===================================================================================================================
การวางโครงร่างฐานข้อมูล (NoSQL Document-Oriented Architecture) มีความยืดหยุ่นสูง เพื่อตอบสนองความเร็วและการบันทึกข้อมูลในสภาวะจำกัด:

-------------------------------------------------------------------------------------------------------------------
1. แผนผังคอลเลกชันหลัก (Primary Firestore Collections Schemas Map)
-------------------------------------------------------------------------------------------------------------------

คอลเลกชันที่ 1: 'users' (สถิติวิศวกรและผู้จัดหาพลังงาน)
  - เส้นทางเอกสาร (Document Path): `/users/{userId}` (ใช้ Firebase Auth UID เป็นชื่อเอกสาร)
  - ข้อมูลภายในฐาน (Fields):
    * employeeId: string (รหัสพนักงาน/เลขประจำตัว)
    * username: string (ชื่อล็อกอิน)
    * name: string (ชื่อระบุตัวตนจริง ภาษาไทย/อังกฤษ)
    * email: string (อีเมลที่ยืนยันแล้ว)
    * phone: string (เบอร์โทรสะดวกสายงาน)
    * role: string_enum ["ADMIN", "INSPECTOR", "MANAGER", "VENDOR"]
    * peaOffice: string (รหัสย่อยสังกัดสำนักงาน กฟจ.)
    * department: string (แผนกปฏิบัติการ)

บทที่ 6: เจาะลึกทางทฤษฎีและสถาปัตยกรรมของระบบพิกัดอัจฉริยะ Geolocation API (Web Geolocation In-depth Principles)

การระบุตำแหน่งสถานที่ของระบบ PEA PQ Smart Tracker ถือเป็นเสาหลักแห่งความสมบูรณ์เชิงความรับผิดชอบ (Data Integrity) 
เพื่อสร้างความโปร่งใสในเอกสารรับประเมินหน้าสนาม

-------------------------------------------------------------------------------------------------------------------
1. เชิงสถาปัตยกรรมความแม่นยำสูง (High-Accuracy Architecture Configuration)
-------------------------------------------------------------------------------------------------------------------
หน้าจอ 'EquipmentInspection.tsx' เรียกใช้งาน HTML5 Geolocation API โดยบังคับขุดสัญญาณผ่านการกำหนดค่าพารามิเตอร์เชิงลึกสูงสุด:
```typescript
{
  enableHighAccuracy: true,
  timeout: 8000,
  maximumAge: 0
}
```
ความหมายของตัวแปรทางเทคนิค (Mathematical & Logical Options Specification):
- 'enableHighAccuracy: true' คือ การสั่งการสั่นรัวเบราว์เซอร์ให้ดึงโมดูเหล็กชิปพิกัดด่านอวกาศ (GPS Hardware Satellites) จากเครื่องโดยตรง 
  เลี่ยงพิกัดไอพี (IP Geo Lookup) ซึ่งก้าวเดินคลาดเคลื่อนได้ถึง 1-5 กิโลเมตร ส่งผลให้ได้รับพิกัดที่แม่นยำในระดับบวกลบไม่เกิน 3-10 เมตรในสภาพฟ้าเปิด
- 'timeout: 8000' จำกัดเวลาให้ระบบค้นหน้าพิกัดเสร็จใน 8 วินาที หากเกิน 8 วินาที (เช่นวิศวกรอยู่ในตู้คอนซิลมืดทึบ หรือพายุเข้านอกสนาม) 
  เซิร์ฟคลาวด์จะตัดช่องทางทำรายการ เข้าสู่ตักเตือน (Timeout Error Event) ป้องกันเว็บบล็อคกระชับโหลดไม่รู้จบ
- 'maximumAge: 0' กำหนดสิทธิ์อายุแคชที่เก็บเป็น 0 บังคับให้เบราเซอร์ลบภาพพิกัดเดิมทุกครั้งที่ตบปุ่ม ตรวจจับสัญญาณพิกัดล่าสุด เพื่อป้องกันการแคชค้างจากการส่งผลงานจุดก่อนหน้า

-------------------------------------------------------------------------------------------------------------------
2. ทฤษฎีความต่างระยะผิวพื้นโค้งแบบ Haversine Formula (Geofencing Mathematical Computation)
-------------------------------------------------------------------------------------------------------------------
เนื่องจากโลกของเราไม่มีรูปทรงเป็นทรงแบนระนาบ การหาระยะห่างทางภูมิศาสตร์บนผิวทรงกลมพิกัดแบนจึงจำเป็นต้องนำค่าสองคู่อัน (Lat1, Lng1) และ (Lat2, Lng2) มาคำนวณผ่าน "สูตรฮาเวอร์ซีน (Haversine Formula)" ในตัวแอปพลิเคชัน:

สูตรคณิตศาสตร์แม่บทหลัก:
  a = sin²(Δlat/2) + cos(lat1) * cos(lat2) * sin²(Δlon/2)
  c = 2 * atan2(√a, √(1-a))
  d = R * c

คำนิยามและการแปลค่าตัวแปร:
- 'Δlat' (Delta Latitude) = lat2 - lat1 (แปลงเข้าสู่หน่วยเรเดียนด้วยตัวคูณ rad = PI / 180)
- 'Δlon' (Delta Longitude) = lon2 - lon1 (แปลงเข้าสู่หน่วยเรเดียน)
- 'R' (Radius of the Earth) = รัศมีเฉลี่ยโค้งขอบทรงกลมโลก = 6,371,000 เมตร
- 'd' = ระยะทางขนานเส้นสัมผัสจริงบนสภาพพื้นผิว (ระยะห่างทางราบ มีหน่วยวัดเป็นเมตร)

ตารางแสดงพารามิเตอร์ขัดขวางทางเทคนิค (Limits Specs):
+-------------------------+--------------------+---------------------------------------------------------------+
| ค่าข้อกำหนดหลัก           | ค่าตัวแปรจำเจ       | คำอธิบายและผลทางขอบเขตธุรกิจ                                   |
+-------------------------+--------------------+---------------------------------------------------------------+
| GEOFENCE_LIMIT          | 500 เมตร           | ขอบข่ายขอบรัศมีวงกลมพิจารณาปิดกั้นวิศวกรรมการโกงข้อมูล            |
| GPS_TIMOUT_MS           | 8,000 มิลลิวินาที  | เวลาสูงสุดที่รอเซนเซอร์การดาวเทียมสะท้อนภาพพิกัด                 |
| SYSTEM_ERROR_W3C_CODE_1 | PERMISSION_DENIED | แสดงป๊อปอัพเตือนว่า "กรุณาเปิดปิดปุ่มกุญแจแชร์โลเคชั่นเบราว์เซอร์" |
| SYSTEM_ERROR_W3C_CODE_2 | POSITION_UNABLE    | สภาพอับระบุพิกัดหรือสไลด์ปิดตัวจำพวง GPS ในระบบมือถือหลัก       |
+-------------------------+--------------------+---------------------------------------------------------------+

บทที่ 7: แผนยุทธศาสตร์และการประยุกต์ใช้โมเดลปัญญาประดิษฐ์ในอนาคต (Future AI Strategic Roadmap)
===================================================================================================================
เพื่อผลักดัน PEA PQ SMART TRACKER สู่การเป็น "Cognitive IoT Assistant" ขอเสนอแผนยุทธศาสตร์บูรณาการโมเดลประมวลผลคำสั่งอัจฉริยะ (Google Gemini 3.5 Flash/Gemini 3.1 Pro via Modern @google/genai Node SDK) ผ่าน 5 ยอดฟีเจอร์นวัตกรรมไฟฟ้า:

1. ฟีเจอร์วิเคราะห์ความปลอดภัยตู้ควบคุมด้วยภาพ Multimodal (AI Switchgear Smart Vision):
   - การประยุกต์ใช้งาน: จัดให้มีโมเดลสแกนเนอร์รูปถ่ายภายนอกและโครงข่ายต่อสายด้านในตู้ รวมถึงภาพสแกนรังสีความร้อนอินฟราเรด (Infrared Thermography)
   - ขีดความสามารถ: จำแนกจุดสนิมกัดกร่อน ขั้วสายยึดหลวมที่เกิดอุณหภูมิสะสม และออกคะแนนความสมบูรณ์เชิงมาตรฐาน (Safety Reliability Index Score 0-100) 
     พร้อมระบุประเภทอุปกรณ์คุ้มครองความปลอดภัย (PPE Safety Level) ที่ผู้ปฏิบัติงานต้องสวมใส่ทันที

2. ฟีเจอร์สั่งรวบคำสั่งตอบโอนฟอร์มด้วยเสียงพูด (Hands-Free AI Voice Co-Pilot):
   - การประยุกต์ใช้งาน: การออกแบบสำหรับวิศวกรที่ห้อยโหนบนเก้าอี้เสาไฟหรือมือถือเครื่องมือจนไม่สะดวกลงพิมพ์แป้น
   - ขีดความสามารถ: ผู้ตรวจสามารถรับบันทึกคลิปเสียงรายงานความยาวสั้น-ยาวภาษาไทยถอดรหัสออกมา และสลับข้อมูลเอาค่าฟิลด์ Voltage, Harmonic, 
     และคราบความต่างขวานสลายวางลงตามฟิลด์แบบฟอร์มบน Firestore เองอัจฉริยะแบบไร้มติข้อขัดข้อง

3. ฟีเจอร์สรุปพอร์ตงานรวบเชิงบริหารสำหรับสั่งอนุมัติ (AI Executive Report Briefing):
   - การประยุกต์ใช้งาน: รองรับผู้ประกอบการฝ่ายบริหารที่มีเวลาจำกัดในการดูสเปกตรวจในแต่ละวัน (Manager Portal)
   - ขีดความสามารถ: กรองดึงภาพถ่าย ลายเซ็น ข้อมูลปัญหา และรายงานการเก็บบันทึก มารวบกระดาษแผ่นย่อไทยสั้นกระชับ (Executive Brief 1 หน้ากระดาษ) 
     ชี้นำสีแดงแดงสำหรับจุดบกพร่องที่ต้องสั่งทำลายหรือซ่อมสวิตช์ด่วน

4. โมเดลพยากรณ์โครงข่ายเสี่ยงดับชำรุดล่วงหน้า (AI Outage Predictor & Scheduler):
   - การประยุกต์ใช้งาน: นำข้อมูลสถิติรายงานย้อนหลังในคลัง ร่วมกับประเภทของสัญญา และข้อมูล Complaints เชิงปริมาณมาประมวลผลรวม
   - ขีดความสามารถ: ตรวจดึงความถดถอยของพลังงานจ่าย สัญญาณรบกวนคลื่นฮาร์มอนิก และประเมินพิกัดความเสี่ยงโรงไฟฟ้าที่กำลังเสี่ยงไฟฟ้าขัดข้อง

5. แชทตอบปัญหาทางกฎเกณฑ์เกณฑ์ไฟฟ้าอัจฉริยะ (PEA PQ Technical Advisor Chat Widget):
